# 모델·실행 라우팅 (상세)

코어 골격(안전 tie-break·게이트=최상위 모델·완료 보고≠검증)은 운영 규칙이 단일 원본이다 — 여기는 라우팅 표와 위임 세칙.

## 상시 규칙

서브에이전트를 띄울 땐 **호출에 `model`을 적지 않는다.**

1. **빼면 무엇이 쓰이나.** 에이전트 설정(frontmatter)에 `model:` 이 선언돼 있으면 그 값이 쓰인다 — 차근의 세 에이전트는 전부 선언돼 있다(2026-08-10 실측: `model` 없이 `code-implementer` 를 띄우니 그 서브에이전트 기록의 모델이 `claude-sonnet-5` 였다. 세션 모델 Opus 를 물려받지 않았다). **선언이 없는 에이전트**(`general-purpose` 등)가 무엇을 쓰는지는 실측한 적이 없다 — 아래 '탐색·조사 위임'이 이 경우를 다룬다.
2. **적으면 오히려 샌다.** 강등 가드는 내리는 것만 막고 올리는 것은 통과시키는데, 등급표가 fable 을 opus 보다 위로 보므로 게이트에 fable 을 적으면 비용 때문에 정해 둔 기본이 그 호출에서 무산된다.
3. **메인 세션이 게이트 기본보다 위여도 적지 않는다.** 비용 결정이 이긴다.
4. **예외는 사용자가 직접 지정한 경우뿐이고, 그때는 그대로 따른다.** 게이트를 기본보다 약한 등급으로 지정하면 훅이 막으니 못 따른다고 알린다. **다만 훅이 막는 범위는 좁다** — `haiku`·`sonnet`·`opus`·`fable` 짧은 이름만 알아보고 `claude-sonnet-5` 같은 정식 ID 는 모르는 값이라 통과시킨다(오차단 0 설계). 훅은 백스톱이지 유일한 방어선이 아니므로 이 판단을 훅에 떠넘기지 않는다. 탈출구는 세션을 켜기 전 `CHAGEUN_ALLOW_GATE_MODEL=1` 뿐이고, **무인 모드에서는 그것마저 무시하고 항상 막는다.**
5. **누가 무엇을 맡나.** 검증 게이트(plan-validator/pr-reviewer)는 **최상위 추론모델**이고 **그 자리가 곧 두 에이전트 설정에 박힌 기본값이다**(그래서 일꾼 등급으로 내려 부르지 않는다). 계획·스펙·아키텍처·복잡한 판단도 최상위지만 전용 에이전트가 없어 **인라인**으로 간다(아키텍처·복잡한 판단은 코어 안전 tie-break 가 Opus 인라인으로 고정). **최종 리뷰는 인라인이 아니라 위의 pr-reviewer 게이트다.** 명확한 기계적 구현(1~2 파일, 받아쓰기 수준)은 `code-implementer`(**Sonnet** 고정).

모델 등급과 실행 방식(인라인/서브에이전트/병렬)은 별개 축 — 아래 표로 조합해 라우팅한다.

**추론 강도(effort):** 게이트는 effort 미고정(세션 강도 상속 — 메인보다 안 약해지게). 절감은 일꾼만: `code-implementer`=`effort: medium`(뒤를 pr-reviewer가 받침). 메인 세션 effort는 차근이 못 건드림.

## GO 후 자동 결정

plan-validator GO(또는 사용자 "진행해도 좋다") 다음, 선택지를 띄우지 않고 **plan 작업 목록을 근거로 모델·실행 방식을 자동 결정해 한 줄로 통보한다**(+ "다르게 할까요?" 한 줄 override). 판정 인자: 작업 수 · 파일 겹침 · 의존성 · 보안/판단 여부 · 규모.

| 상황 | 모델·실행 |
| --- | --- |
| 보안·판단·권한·동시성·아키텍처·애매·복잡 | **Opus 인라인** (안전 바닥 — 절대 Sonnet 아님) |
| 명확·기계적(보안·판단 무관) · 2개+ 독립·파일 분리 | **Sonnet 서브에이전트 병렬** (아래 '병렬 위임' 규칙 — SDD는 태스크별 순차라 병렬 구현엔 안 씀) |
| 명확·기계적 · 단일 · 1~2파일 안의 반복·분량(경계 지어짐) | **Sonnet 서브에이전트 단일** (`code-implementer`; 스폰 비용보다 이득일 때; 파일 많으면 병렬 2개+ 또는 Opus) |
| 여러 파일 통합·디버깅 | **Sonnet** (애매하면 Opus) |
| 단일 · 자잘(한두 줄) | **인라인 즉시** (스폰 오버헤드 회피, 세션 모델) |
| 독립성·명확성·안전성이 애매 | **인라인 Opus** (fail-safe: 안전하게 비싼 쪽) |

**코어의 안전 tie-break가 이 표보다 항상 우선한다** — 보안·판단·권한·동시성·아키텍처가 조금이라도 걸리면 규모·명확성·반복성 무관 무조건 Opus 인라인.

## 병렬 위임

요청 없어도 독립적(서로 다른 파일) 기계적 작업이 2개 이상이면 기본으로 `code-implementer`(Sonnet) 여러 개를 한 응답에 동시에 띄운다. 단:
- 같은 파일 동시 수정 금지(순차, 또는 `using-git-worktrees`로 worktree 격리 — 즉흥 생성 말고 스킬 절차로).
- **공유·등록류 파일**(라우터 등록·index/barrel export·공통 타입·DB 마이그레이션)은 병렬의 숨은 충돌점 → 병렬에서 빼고 메인이 병렬 완료 후 순차 통합.
- 의존성 있거나(B가 A 결과 필요) 보안·권한·동시성처럼 판단 중요한 코드는 병렬 금지(순차 또는 Opus 직접).
- 독립성·명확성이 애매하면 위임하지 말고 Opus가 직접 구현한다("애매하면 Opus", 한 줄 알림).
- **완료 보고 ≠ 검증:** 서브에이전트가 "다 됐다"고 해도 그대로 믿지 않는다 — 위임한 변경은 실제 바뀐 파일(diff)을 확인한 뒤에만 완료로 치고 다음 작업을 쌓는다(게이트 전·게이트 없는 변경에서 거짓 완료 차단).

## 탐색·조사 위임 (읽기 위임)

읽기·검색·조사를 메인에서 하면 그 내용이 세션 끝까지 남아 **매 턴 다시 읽힌다**(실측 2026-08-04: 대화 누적의 76%가 도구 결과). 분량 있는 탐색은 위임이 이득이고 **격리 이득은 모델과 무관** — 품질이 걱정되면 모델을 낮추지 말고 최상위 모델로 격리만 취한다. 여기가 위 1번의 미실측 구간과 만나는 자리다: `model:` 선언이 없는 에이전트(`general-purpose`·`Explore` 등)에 탐색을 맡길 땐 무엇이 도는지 확인된 바 없으니, **최상위가 필요한 탐색이면 전용 에이전트를 쓰거나 메인이 직접 한다**(모델을 적어 올리는 쪽으로 풀지 않는다 — 위 2번).

**단 탐색엔 판단이 섞인다.** "무엇이 관련 있나"를 서브가 정하고, 뺀 것을 **메인은 빠진 줄 모른다** — 구현 위임의 거짓 완료는 diff로 잡히지만 탐색 유실은 잡을 diff가 없다.

**가르는 기준 = 틀렸을 때 메인이 알아챌 수 있나:** 검증 가능한 사실 조회("어디서 호출되나"·"이 키가 있나")는 위임. "관련된 걸 다 찾아줘"·"왜 이렇게 됐나"·안전/권한/데이터 경계 조사는 메인 직접(코어 tie-break).

**탐색 보고 ≠ 검증:** 위임 지시문에 **본 범위**(실제로 연 경로·검색어) · **제외한 것과 이유**("없었다"와 "안 봤다"를 구분) · **확신 없는 지점**을 함께 요구하고, 빠진 보고는 완료로 치지 않는다. 메인은 결론이 아니라 앞의 둘로 "왜 그건 안 봤지"를 잡는다 — 조용한 유실을 보는 유일한 창.

`subagent-driven-development`(태스크별 순차 plan 실행) 능력은 통보 한 줄로 노출되어 사라지지 않는다 — 위 '병렬 위임'과 별개다(SDD는 병렬 구현 아님).
