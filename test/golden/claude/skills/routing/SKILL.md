# 모델·실행 라우팅 (상세)

코어 골격(안전 tie-break·게이트=최상위 모델·완료 보고≠검증)은 운영 규칙이 단일 원본이다: 여기는 라우팅 표와 위임 세칙.

## 상시 규칙

서브에이전트를 띄울 땐 **호출에 `model`을 적지 않는다.**

1. **빼면 무엇이 쓰이나.** 에이전트 설정(frontmatter)에 `model:`이 선언돼 있으면 그 값이 쓰인다 - 차근의 다섯 에이전트(`code-implementer`·`deep-implementer`·`plan-validator`·`pr-reviewer`·`supervisor`)는 전부 선언돼 있다(2026-08-10 실측: `model` 없이 `code-implementer`를 띄우니 그 서브에이전트 기록의 모델이 `claude-sonnet-5` 였다. 세션 모델 Opus를 물려받지 않았다). **선언이 없는 에이전트**(`general-purpose` 등)가 무엇을 쓰는지는 대개 실측한 적이 없다: 내장 `Plan` 만 예외로, 선언 없이 세션 모델(`claude-opus-5`)을 물려받는 것을 봤다(**관측 1회 · 계획을 맡기기 전에 한 번 다시 본다**). 나머지는 아래 '탐색·조사 위임'이 다룬다.
2. **적으면 오히려 샌다.** 강등 가드는 내리는 것만 막고 올리는 것은 통과시키는데, 등급표가 fable을 opus보다 위로 보므로 게이트에 fable을 적으면 비용 때문에 정해 둔 기본이 그 호출에서 무산된다.
3. **메인 세션이 게이트 기본보다 위여도 적지 않는다.** 비용 결정이 이긴다.
4. **예외는 사용자가 직접 지정한 경우뿐이고, 그때는 그대로 따른다.** 게이트를 기본보다 약한 등급으로 지정하면 훅이 막으니 못 따른다고 알린다. **다만 훅이 막는 범위는 좁다**: `haiku`·`sonnet`·`opus`·`fable` 짧은 이름만 알아보고 `claude-sonnet-5` 같은 정식 ID는 모르는 값이라 통과시킨다(오차단 0 설계). 훅은 백스톱이지 유일한 방어선이 아니므로 이 판단을 훅에 떠넘기지 않는다. 탈출구는 세션을 켜기 전 `CHAGEUN_ALLOW_GATE_MODEL=1` 뿐이고, **무인 모드에서는 그것마저 무시하고 항상 막는다.**
5. **누가 무엇을 맡나.** 검증 게이트(plan-validator/pr-reviewer)는 **최상위 추론모델**이고 **그 자리가 곧 두 에이전트 설정에 박힌 기본값이다**(그래서 일꾼 등급으로 내려 부르지 않는다). **스펙·설계는 최상위 인라인**이다(그 대화는 `chageun:planning` 이 끌고 간다). **구현 계획서는 내장 `Plan` 에이전트**가 쓴다: 파일을 못 쓰므로 그 결과를 메인이 `docs/plans/` 에 옮겨 적는다. **`Plan` 에이전트가 없는 판이면 메인이 최상위 모델로 계획서를 직접 쓴다. 흐름을 멈추지 않는다.** **아키텍처·복잡한 판단이 걸린 구현은 `deep-implementer`(최상위 고정)에 백그라운드로 넘긴다** : 코어 안전 tie-break 가 모델 등급만 고정하고 실행 위치는 라우팅 표에 맡긴다. **최종 리뷰는 인라인이 아니라 위의 pr-reviewer 게이트다.** 명확한 기계적 구현(1~2 파일, 받아쓰기 수준)은 `code-implementer`(**Sonnet** 고정).

**띄울 때 `description` 은 한국어 15자 안쪽으로 짧게 짓는다.** 그 글자는 나중에 사용자 화면(세션 목록·사이드바)에 그대로 뜨는 **이름**이라, 길면 앞부분만 남고 잘려 무슨 일이 도는지 알 수 없다(실측: `계획서…` · `P…`). 개발자용 식별자가 아니라 사용자가 읽는 이름이다.

모델 등급과 실행 방식(서브에이전트 단일/병렬)은 별개 축: 아래 표로 조합해 라우팅한다. **코드 편집에는 인라인 칸이 없다**(코어 B줄) : 인라인으로 남는 것은 계획서·문서·상황판·메모리와 저장소 살림 파일(무시 목록·설정)뿐이다.

**추론 강도(effort):** 게이트는 effort 미고정(세션 강도 상속: 메인보다 안 약해지게). 절감은 일꾼만: `code-implementer`=`effort: medium`(뒤를 pr-reviewer가 받침). **`deep-implementer`는 effort 미고정(세션 강도 상속)**: 판단이 걸린 일을 맡으므로 절감 대상이 아니다. 메인 세션 effort는 차근이 못 건드림.

## GO 후 자동 결정

plan-validator GO(또는 사용자 "진행해도 좋다") 다음, 선택지를 띄우지 않고 **plan 작업 목록을 근거로 모델·실행 방식을 자동 결정해 한 줄로 통보한다**(+ "다르게 할까요?" 한 줄 override). 판정 인자: 작업 수 · 파일 겹침 · 의존성 · 보안/판단 여부 · 규모.

| 상황 | 모델·실행 |
| --- | --- |
| 보안·판단·권한·동시성·아키텍처·애매·복잡 | **`deep-implementer` 백그라운드** (안전 바닥: 절대 Sonnet 아님) |
| 명확·기계적(보안·판단 무관) · 2개+ 독립·파일 분리 | **Sonnet 서브에이전트 병렬** (아래 '병렬 위임' 규칙: 태스크별 순차 실행과는 다른 축이라 그 경로로 병렬 구현을 하지 않는다) |
| 명확·기계적(보안·판단 무관) · 단일 · 1~2파일 · 크기 하한 없음(한두 줄도 여기) | **Sonnet 서브에이전트 단일** (`code-implementer`; **스폰 비용이 아깝게 느껴져도 인라인으로 되돌리지 않는다 - 그 칸은 없앴다**; 파일 많으면 병렬 2개+ 또는 최상위 모델) |
| 여러 파일 통합·디버깅 | **Sonnet** (애매하면 `deep-implementer`) |
| 독립성·명확성·안전성이 애매 | **`deep-implementer` 백그라운드** (fail-safe: 안전하게 비싼 쪽) |
| 여러 바퀴(수정 → 검토 → 수정)가 예상 · 메인 대화창을 아끼고 싶을 때 | **`supervisor` 백그라운드** (부를 때만 - 기본 경로는 그대로다. 한 번에 끝날 일에 끼우면 왕복만 한 겹 는다. **결과를 보며 다음 수를 고쳐야 하면 각본이 아니라 에이전트다** : 감독의 루프는 게이트 판정을 읽고 다음에 무엇을 고칠지 정하는 일이라 미리 적어 둔 각본으로 굳힐 수 없는 종류다. **감독은 `Agent` 로 띄운다(각본으로 안 띄운다).**) |

**코어의 안전 tie-break가 이 표보다 항상 우선한다** : 보안·판단·권한·동시성·아키텍처가 조금이라도 걸리면 규모·명확성·반복성 무관 무조건 **최상위 모델**이다(절대 Sonnet 아님). tie-break 가 정하는 것은 **모델 등급 하나뿐이고, 실행 위치는 정하지 않는다** : 그 자리는 아래 '위임과 BLOCKED 계약' 이 정한다.

## 위임과 BLOCKED 계약

1. **모델 등급과 뒤로 돌리기는 별개 축이다.** 뒤로 돌린다고 모델을 낮추지 않는다. 판단이 걸린 일은 **최상위 모델을 백그라운드로** 띄운다(`deep-implementer`).
2. **BLOCKED 계약(핵심 안전 요건).** 뒤에서 도는 일이 **결정 지점**(성공 기준·범위 변경 / 보안·권한·데이터 경계 선택 / 같은 문제 2회 실패 / 되돌리기 어려운 행동)에 닿으면 **혼자 정하지 말고 그 자리에서 멈추고 BLOCKED 로 보고한다.** 메인은 그 보고를 **즉시** 사용자에게 선택지로 올린다.
3. **작업 시작 카드는 위임 전에 메인이 띄운다.** 뒤로 넘긴 뒤에는 사용자가 볼 자리가 없다.
4. **완료 보고 ≠ 검증**(기존 규칙 상속). 뒤에서 왔어도 바뀐 파일(diff)을 확인한 뒤에만 완료로 친다.
5. **게이트는 메인만 띄운다.** 구현한 에이전트가 자기 검사를 부르게 두지 않는다. 만든 쪽이 검사 범위를 고르게 되어 독립성이 깨지고, 판정이 세 단계로 요약되며, 비용이 화면 밖에서 늘어난다. 게다가 게이트를 스스로 띄우면 자기 기록에 실행 흔적이 생겨 **자기 push 잠금까지 풀린다**: 그래서 훅이 서브에이전트의 게이트 스폰을 기계로 막는다. **중첩 스폰은 안 한다** : 뒤에서 도는 에이전트는 조사·탐색이라도 다른 서브에이전트를 띄우지 않는다(구현 에이전트 계약과 같은 말이다). 일이 갈라지면 메인이 갈라야 사람이 볼 수 있다. 기계가 막는 것은 게이트 스폰뿐이고 나머지는 이 계약이 막는다. **예외는 감독(`supervisor`) 하나다.** 위 네 이유 중 감독이 무효화하는 것은 하나뿐이라 나머지 셋은 따로 값을 치른다 : **자기 push 잠금**은 안 풀린다(서브에이전트의 올리기는 훅이 무조건 막고, 메인은 올리기 전에 자기 기록에서 검토를 한 번 더 돌린다). **판정 요약**은 겹이 안 는다(감독은 판정 원문을 한 글자도 안 줄이고 그대로 올린다). **검사 범위**는 감독도 고르므로, 감독은 범위를 좁히지 않고 계획서 전체 또는 브랜치 전체 diff 를 넘긴다. **비용**은 스폰 상한이 막고, 그 상한은 못 읽으면 통과가 아니라 멈춘다. 감독을 띄울 수 있는 것은 메인뿐이고, 일꾼은 여전히 게이트를 못 띄운다.
6. **push·PR 은 메인 세션이 한다.**
7. **게이트를 통과한 뒤 위임으로 고친 것이 있으면 push 전에 메인 세션이 게이트를 다시 돌린다.**
   신선도 훅은 **이 세션 기록 안의 편집만** 센다. 서브에이전트가 고친 것은 메인 기록에 안 남아
   검사가 스스로 깨지지 않는다. 즉 게이트 통과 뒤 위임으로 한 줄이라도 고쳤으면, 훅이 통과시켜도
   **그 코드는 검사를 안 받은 코드다.** 위임 결과를 받은 메인 세션이 직접 판단해서 다시 돌린다.
   판단 기준은 하나다 : **게이트를 돌린 뒤에 코드 파일이 바뀌었나.** 바뀌었으면 다시 돌린다.
8. **코어 B줄이 이미 더 넓게 막는다**(제품 코드는 인라인 편집 금지). 이 항은 그중 **가장 위험한 경우를 다시 적은 것**이지 "위임 중이 아닌 파일은 만져도 된다"는 뜻이 아니다. **위임 중인 파일은 메인이 인라인으로 건드리지 않는다.** 그 파일은 작업방 브랜치에 있어서, 메인이 본 폴더에서 같은 파일을 고치면 합칠 때 충돌하거나 한쪽이 조용히 사라진다(아래 '병렬 위임'의 같은 파일 금지가 메인에도 그대로 적용된다). 급하면 위임 결과를 받은 뒤에 고친다.
9. **상황판.** 이 프로젝트에 `status.md` 가 있으면, **§2(지금 뒤에서 도는 것)는 손대지 않는다: 기계가 쓴다.** 사람 몫은 둘이다: 끝난 일을 §5로 옮기고, BLOCKED로 오면 §1에 올린다. **상황판이 없으면 여기서 만든다**(카드를 건너뛴 일이 뒤로 도는 일로 커진 경우를 잡는 백스톱). 상세: `chageun:statusboard`.

## 작업방에서 굴린다

구현 위임은 **전용 작업방(git worktree)** 에서 돈다. 병렬 전용이 아니라 **모든 구현 위임**에 걸린다.

1. 작업방은 `Agent(isolation: "worktree")` 가 만든다. 손으로 `git worktree add` 하지 않는다. **무인 세션은 방을 만들지 않는다** : 이미 격리 저장소 안이고 `.claude/` 아래 쓰기가 기계로 막혀 있다(코어 A줄 예외와 같은 말). **작업방을 못 만드는 판(git 저장소가 아님 · 도구 오류)이면 그 사실을 알리고 `git init` 을 먼저 제안한다.** 그 전까지는 방 없이 위임하고, **방 없이 돌았다는 사실을 보고에 적는다.** 조용히 인라인으로 되돌아가는 갈래는 열지 않는다.
2. **만들기 전에는 남은 방을 세기만 한다.** 개수와 대략 크기를 진행 보고에 한 줄로 적고 **지우지는 않는다** : 치우는 것은 판이 끝난 뒤 9번에서 한 번에 한다. 위임할 때마다 승인을 받으면 한 줄 고치는 일마다 멈춤이 된다. **다만 문턱을 둔다** : 센 결과가 **8개** 또는 대략 **2GB** 를 넘으면 그 자리에서 한 번 올린다. 문턱이 없으면 "세기만 한다"는 아무것도 안 하는 것과 같다.
3. **방을 처음 만들기 전에 그 경로가 git 무시 대상인지 한 번 확인한다.** 방은 저장소 **안**(`.claude/worktrees/`)에 생기므로, 무시 목록에 없는 프로젝트에서는 본 폴더의 `git status`·`git add -A`·미추적 검수·`Grep` 결과에 방 사본이 통째로 섞인다. 안 되어 있으면 상황판 절차처럼 `<git-common-dir>/info/exclude` 에 한 줄 넣는다.
4. **계획서는 본 폴더 절대경로로 넘긴다.** 작업방에 `docs/` 가 없을 수 있다(이 저장소는 `docs/` 가 git 밖이다). 작업방 안에서 계획서를 찾게 두지 않는다.
5. 돌려봐야 하는 일이면 **환경을 먼저 채운다.**
   - `.env` 는 **`cp` 로만 옮긴다.** Read/Write 로 옮기지 않는다 : 차근의 기계 바닥이 `.env` 값을 도구 출력에서 가리므로 **가려진 글자가 그대로 새 파일에 적혀 파일이 조용히 망가진다.** 그 파일로 띄운 서버는 반쪽으로 떠서 "구동 검증 통과"가 거짓 초록이 된다. 옮긴 사실만 보고하고 값도 파일 이름도 인용하지 않는다.
   - `node_modules` 는 복사하지 말고 심볼릭 링크를 건다(0바이트). **다만 링크를 건 작업방에서는 `npm install`·`npm ci` 를 돌리지 않는다** : 링크는 본 폴더의 설치물과 **같은 하나**라, 거기서 설치하면 본 폴더와 다른 모든 작업방이 동시에 바뀐다. 의존성이 바뀌는 일이면 그 작업방에 따로 설치하거나 BLOCKED 로 올린다.
   - 빌드 캐시는 안 옮긴다.
6. 완료 보고에 **작업방 경로와 브랜치**를 함께 받는다. 그 둘이 없으면 완료로 안 친다.
7. diff 는 `git -C <작업방> diff <본가지>...HEAD` 로 본다. **경로만이 아니라 견줄 기준까지** 게이트 지시문에 못박는다. 일꾼이 커밋까지 하므로 그냥 `diff` 는 빈 결과이고, 그러면 게이트가 실패가 아니라 **통과**로 끝난다. 아직 커밋 안 한 것은 `git -C <작업방> status --porcelain` 으로 함께 본다. 감독(`supervisor`)은 `git` 을 못 쓰므로 바뀐 파일의 절대경로를 준다.
8. **구동 검증도 작업방에서 한다.** 본 폴더에서 띄우면 안 고친 코드를 검증한다. 작업방에서 띄운 서버는 메인이 안 거두므로 직접 내린다.
9. **판이 다 끝난 뒤 한 번에 정리한다.** 위임 회차마다가 아니다.
   - (가) 합치기가 성공한 것을 눈으로 확인한 방이 대상이다. 충돌이 났거나 BLOCKED 로 선 방은 지우지 않는다.
   - (나) **이번 판과 무관한 옛 방도 같은 목록에 넣는다.** "이번 판에서 잘 합쳐진 방"만 대상으로 잡으면 지난 판이 남긴 방은 **어느 절차에도 안 잡혀 영원히 남는다.** 옛 방은 브랜치가 본가지에 이미 들어갔는지 확인한 뒤 같은 승인 묶음에 올린다.
   - (다) 대상 방 목록을 **한 번에 모아** 사용자에게 올리고 **승인을 한 번 받는다.** 코어 멈춤 규칙이 파일 삭제 앞에서 멈추라고 하는데, 그 멈춤을 판마다 한 번으로 모으는 것이다.
   - (라) 지우기는 `git worktree remove` 로만 한다. **`--force` 는 쓰지 않는다.**
   - (마) 거부당하면(저장 안 된 변경이나 미추적 파일이 있다는 뜻) 지우지 말고 그 방을 **'보류' 목록**에 남긴다. 같은 보고를 매번 되풀이하지 말고, 보류 목록을 상황판 §7에 한 줄로 적어 다음 판이 이어받게 한다.
   - (바) 환경 파일을 복사해 뒀으면 방과 함께 없어지는지 확인한다.

## 병렬 위임

요청 없어도 독립적(서로 다른 파일) 기계적 작업이 2개 이상이면 기본으로 `code-implementer`(Sonnet) 여러 개를 한 응답에 동시에 띄운다. 단:
- 같은 파일 동시 수정 금지(순차, 또는 작업방 격리 - 위 '작업방에서 굴린다').
- **공유·등록류 파일**(라우터 등록·index/barrel export·공통 타입·DB 마이그레이션)은 병렬의 숨은 충돌점 → 병렬에서 빼고 메인이 병렬 완료 후 순차 통합.
- 의존성 있거나(B가 A 결과 필요) 보안·권한·동시성처럼 판단 중요한 코드는 **병렬 금지**(순차). 그 일은 `code-implementer` 여러 개로 쪼개지 말고 `deep-implementer` 하나에 순차로 맡긴다 : 막는 것은 **병렬**이지 위임이 아니다.
- 독립성·명확성이 애매하면 `code-implementer` 로 쪼개지 말고 `deep-implementer`(최상위) 하나에 통째로 맡긴다("애매하면 최상위", 한 줄 알림). fail-safe 방향은 그대로다 : 안전하게 비싼 쪽.
- **완료 보고 ≠ 검증:** 서브에이전트가 "다 됐다"고 해도 그대로 믿지 않는다 - 위임한 변경은 실제 바뀐 파일(diff)을 확인한 뒤에만 완료로 치고 다음 작업을 쌓는다(게이트 전·게이트 없는 변경에서 거짓 완료 차단).

## 탐색·조사 위임 (읽기 위임)

읽기·검색·조사를 메인에서 하면 그 내용이 세션 끝까지 남아 **매 턴 다시 읽힌다**(실측 2026-08-04: 대화 누적의 76%가 도구 결과). 분량 있는 탐색은 위임이 이득이고 **격리 이득은 모델과 무관**: 품질이 걱정되면 모델을 낮추지 말고 최상위 모델로 격리만 취한다. 여기가 위 1번의 미실측 구간과 만나는 자리다: `model:` 선언이 없는 에이전트(`general-purpose`·`Explore` 등)에 탐색을 맡길 땐 무엇이 도는지 확인된 바 없다. **확인되기 전까지는 최상위가 필요한 탐색을 메인이 직접 한다** - 컨텍스트 절감을 그만큼 포기하는 것이며, 실측되면 되돌린다(모델을 적어 올리는 쪽으로 풀지 않는다: 머리의 무조건 규칙과 3번(비용)).

**단 탐색엔 판단이 섞인다.** "무엇이 관련 있나"를 서브가 정하고, 뺀 것을 **메인은 빠진 줄 모른다**: 구현 위임의 거짓 완료는 diff로 잡히지만 탐색 유실은 잡을 diff가 없다.

**가르는 기준 = 틀렸을 때 메인이 알아챌 수 있나:** 검증 가능한 사실 조회("어디서 호출되나"·"이 키가 있나")는 위임. "관련된 걸 다 찾아줘"·"왜 이렇게 됐나"·안전/권한/데이터 경계 조사는 메인 직접. **근거는 바로 위 줄이다** : 탐색 유실은 잡을 diff 가 없어 메인이 빠진 줄 모른다. (코어 tie-break 를 근거로 대지 않는다 : tie-break 는 모델 등급만 정하고 실행 위치는 정하지 않는다.)

**탐색 보고 ≠ 검증:** 위임 지시문에 **본 범위**(실제로 연 경로·검색어) · **제외한 것과 이유**("없었다"와 "안 봤다"를 구분) · **확신 없는 지점**을 함께 요구하고, 빠진 보고는 완료로 치지 않는다. 메인은 결론이 아니라 앞의 둘로 "왜 그건 안 봤지"를 잡는다: 조용한 유실을 보는 유일한 창.

태스크별 순차 계획 실행의 주인은 `chageun:routing` 의 위임이다(병렬 위임과는 별개 축이다). 실행 중 단계 체크는 계획서 안의 `- [ ]` 토글로 한다.
