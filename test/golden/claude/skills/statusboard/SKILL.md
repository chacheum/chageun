# 작업 상황판 (statusboard)

자리를 비운 사이 뒤에서 여러 일이 돈다. 돌아왔을 때 **무엇이 끝났고 내가 무엇을 해야 하나**를 한 장에서 보는 파일이 상황판이다.

- **원본은 파일 하나다**: 켠 폴더(`cwd`)의 `status.md`. 서버가 없어도 파일만 열면 된다.
- **파일 이름은 언어와 무관하게 `status.md` 하나다.** 파일 **안의** 제목·본문은 사용자 언어 그대로 쓴다.
- 보는 페이지(웹)는 여러 상황판을 **모아 보여 줄 뿐** 만들지도 고치지도 않는다.

## 칸 골격 (순서 고정)

```
# <프로젝트> 작업 상황판
## 1. 지금 하실 것: N건
## 2. 지금 뒤에서 도는 것: N건
## 3. 진행 중인 판
## 4. 제가 정한 것
## 5. 끝난 것
## 6. ⚠ 알아 두실 것
## 7. 다음 판 후보
```

- **1·2번은 필수**다. 나머지는 내용이 있을 때만 쓴다(빈 칸으로 자리만 차지하지 않는다).
- **1·2번 제목에는 개수를 숫자로 적는다** — 형식은 `하실 것: N건`.
- **호칭을 넣지 않는다.** `지금 하실 것` 처럼 중립어로 쓴다.
- 본보기는 이 폴더의 `board.template.md` 다.

## 기계가 쓰는 칸

1. **§2(지금 뒤에서 도는 것)는 기계가 쓴다** — `<!-- chageun:auto -->` 와 `<!-- /chageun:auto -->` 사이, 그리고 머리의 `<!-- chageun:auto:head -->` 사이는 **손으로 쓰지 않는다**(다음 갱신에 지워진다).
2. 나머지 여섯 칸은 그대로 사람이 쓴다.
3. 표시를 지우면 **그 칸의 자동 갱신이 꺼진다**(다른 칸·다른 프로젝트는 그대로).

## 갱신 규칙

- **위임을 띄우거나 끝났을 때**: §2는 기계가 쓴다 — 손대지 않는다. 사람 몫은 둘, 끝난 일을 §5로 옮기고 BLOCKED로 오면 §1에 올린다.
- **끝 점검**: §4·§5·§6을 갱신한다.
- **사용자가 "그거 했다" 하면 그 자리에서 §1에서 지운다.** 안 지우면 끝난 일이 영원히 남는다.
- **고칠 때는 파일 전체를 덮어쓰지 말고 그 칸만 고친다**(`Edit`). 한 폴더에 세션이 둘이면 전체 덮어쓰기가 상대 글을 조용히 지운다.
- **비밀번호·열쇠 값·고객 정보·회사 내부 주소는 적지 않는다.** 상황판은 비밀번호 없는 평문 보고서다.

## 처음 만들 때

**만들지 말지 판단선:** 뒤에서 돌 일이 생기거나 사용자가 결정할 것이 생기는 일이면 만든다. **파일 하나를 15분 안에 고치고 끝나는 일이면 안 만들어도 된다.** 예외 둘 — 사용자가 "상황판 켜줘" 하면 규모와 무관하게 만들고, 상황판 없이 뒤로 돌리는 일이 생기면 그 자리에서 만든다.

🛑 **파일부터 만들지 않는다. 아래 무시 절차를 먼저 밟는다** — 상황판은 평문 업무 보고라 저장소에 올라가면 이력에 남는다.

1. **저장소인가** — `git rev-parse --path-format=absolute --git-common-dir`.
   실패(종료코드 128)하면 git 저장소가 아니다. **상황판은 그대로 만들고**, 무시 줄은 건너뛰고 한 줄만 알린다: "이 폴더는 git 이 아니라 막을 것이 없습니다." `git init` 도 `.gitignore` 도 만들지 않는다.
   ⚠ `--path-format=absolute` 를 빼면 하위 폴더에서 켰을 때 `../.git` 같은 상대 경로가 나와 무시 줄이 엉뚱한 자리에 들어간다.
2. **이미 추적 중인가** — `git ls-files --error-unmatch status.md` 가 0이면 이미 git 이 들고 있다. **여기서 멈춘다: 파일도 안 만들고 무시 줄도 안 넣는다.** 사용자에게 `git rm --cached status.md` 를 그대로 보여 주고, (1) 이미 올라간 커밋 이력은 그 명령으로 안 지워진다는 것과 (2) **추적을 끊은 뒤에 3~5번을 한 번 더 밟아야 실제로 막힌다**는 것을 함께 적는다. **자동 실행 금지** — 저장소 이력에 손대는 일이다.
3. **이미 무시되나** — `git check-ignore -q status.md`. **0이면 이미 무시됨**(4번 건너뜀) · **1이면 4번으로** · **128이면 오류라 멈추고 알린다**.
4. **한 줄 넣기** — `<git-common-dir>/info/exclude` 끝에 주석 한 줄과 `status.md` 를 덧붙인다. `info/` 폴더가 없으면 먼저 만든다. 파일 끝에 개행이 없으면 개행부터 넣는다.
5. **재확인** — `git check-ignore -q status.md` 를 한 번 더 돌린다. **0일 때만** "상황판은 git 에 안 올라갑니다(이 컴퓨터에만 적용)"라고 알린다. **0이 아니면 그 말을 하지 말고** "무시 줄을 넣었는데 git 이 여전히 추적 대상으로 봅니다"라고 알린다(`.gitignore` 의 되살림 규칙 `!status.md` 는 `info/exclude` 를 이긴다 · 쓰기 실패도 여기서 잡힌다).
6. **무시가 확인된 뒤에 상황판 파일을 만든다.** `board.template.md` 를 복사해 §1은 `0건`, §3에 지금 하는 일의 목표 한 줄을 넣는다.
   🛑 **파일은 `Write` 도구로 만든다. Bash 리다이렉션 금지**(`cat > … <<EOF` · `echo … >` · `tee`) — 안전 검사는 `Write`·`Edit`·`MultiEdit` 에만 걸려 있어 Bash 로 만들면 비밀 값 검사도 무시 확인 백스톱도 통째로 비켜 간다.

**왜 `.gitignore` 가 아니다:** `.gitignore` 는 막는 줄 자체가 커밋돼 저장소에 남고, 팀이 함께 보는 파일을 사용자 모르게 고치게 된다. `info/exclude` 는 상황판도 막는 줄도 아무것도 안 올라간다. 팀과 공유하려면 사용자 한마디로 `.gitignore` 로 옮긴다.

## 이미 있을 때

이 프로젝트에 `status.md` 가 **이미 있고** 이번 세션에서 아직 확인 안 했으면, **고치기 전에** 한 번 확인한다.

1. **무시 확인이 먼저다** — `git check-ignore -q status.md` 가 **0이면 그대로 쓴다**(알릴 것도 없다). **0이 아니면** 위 절차를 1→5번까지 밟는다(**6번은 건너뛴다** — 파일이 이미 있다).
   🛑 **이미 추적 중이면 아무것도 고치지 않고 사용자에게 알린다.** 무시 줄도 안 넣고 `git rm --cached` 도 안 돌린다. 계속 쓸지 추적을 끊을지는 사용자가 정한다. **회복이 두 걸음**(추적 끊기 → 무시 절차 다시)이라는 것도 함께 적는다.
2. **표시 두 벌이 있는지 본다** — `<!-- chageun:auto -->`~`<!-- /chageun:auto -->`(§2) · `<!-- chageun:auto:head -->`~`<!-- /chageun:auto:head -->`(머리 블록).
   - **한 벌이라도 짝이 안 맞으면 그 자리에 넣는다** — §2 표시는 `## 2.` 제목 **바로 위**와 그 칸 끝, 머리 표시는 부제 줄 **다음**. 넣는 것은 **표시 두 줄뿐**이고 사람 글은 한 글자도 안 건드린다. **`Edit` 로 그 자리만** 고친다.
   - 한쪽만 있는 파일도 대상이다(머리 표시만 있고 §2 표시가 없는 모양이 흔하다).
   - 표시를 넣은 뒤 한 줄 알린다: **§2 칸 안에 손으로 써 둔 글은 다음 갱신에 지워진다**(남길 것이 있으면 §3으로 옮기라고).
   - 🛑 **순서를 지킨다: 무시 확인이 먼저, 표시 넣기가 나중이다.** 표시를 넣는 그 편집 자체가 안전 검사의 신호에 걸려, 무시가 아직 확인 안 됐으면 그 자리에서 막힌다.

## 답장 끝에 주소 달기 (사다리 3단 · 되는 것 하나만)

**주소를 손으로 박지 않는다.** `${XDG_CACHE_HOME:-~/.cache}/chageun/board.json` 의 `{host, port}` 를 먼저 읽고, 그 파일이 없을 때만 `127.0.0.1:8095` 를 시도한다(8095가 남의 서버면 서버가 8096~8104로 밀려 있다).

떠 있는지 보는 명령:

```sh
curl -sfI -m 1 "http://$HOST:$PORT/" | grep -qi '^x-chageun-board:'
```

헤더까지 봐야 남의 서버를 상황판으로 착각하지 않는다.

1. 아무것도 없으면 → `프로젝트이름/status.md` (홈 경로는 안 적는다)
2. 보는 페이지가 떠 있으면 → `http://<host>:<port>/#<조각>` (보던 탭까지 · `<조각>` 은 폴더 이름에서 `[^A-Za-z0-9_-]` 를 `-` 로 바꾼 것)
3. 이미 tailscale 이 그 포트에 붙어 있으면 → 그 주소. 차근이 `tailscale funnel` 을 켜지는 않는다.

## 보는 페이지 띄우기

`board-server.mjs` 경로는 아래 순서로 찾는다.

1. 세션 시작 안내에 박힌 절대 경로
2. `$CLAUDE_PLUGIN_ROOT` (Bash 도구에서는 비어 있을 수 있다)
3. `find ~/.claude/plugins -maxdepth 8 -name board-server.mjs -path '*chageun*' 2>/dev/null | head -1`

**셋 다 실패하면 경로를 지어내지 말고 못 찾았다고 알리고 멈춘다.**

띄우는 법: `node <경로> &` — 기본은 `127.0.0.1:8095` 이고 **이 컴퓨터에서만** 열린다. 환경변수 `CHAGEUN_BOARD_HOST`·`CHAGEUN_BOARD_PORT`·`CHAGEUN_BOARD_ROOT` 로 바꿀 수 있고, 무인 모드에서는 host 설정을 무시하고 loopback 으로 고정한다.

## 밖에서(다른 사람도) 여는 법

기본은 이 컴퓨터에서만 열린다. 밖에서 열려면 아래 중 하나를 **사용자가 직접** 고른다.

| 방법 | 좋은 점 | 걸리는 점 |
|---|---|---|
| 테일스케일 | 설정이 가장 쉽고 주소가 밖으로 안 샌다 | **보는 사람도 계정을 만들고 앱을 깔아야** 한다. Funnel 로 공개하면 안 깔아도 되지만 그때는 비밀번호 없이 인터넷에 열린다 |
| Cloudflare Tunnel | 보는 사람은 브라우저만 있으면 된다 | 기본이 완전 공개라 비밀번호를 따로 걸어야 하고 계정·도메인 설정이 필요하다 |
| 직접 서버에 올리기 | 늘 켜져 있다 | 파일이 이 컴퓨터에 있어 계속 올려 보내야 하고, 그 통로가 새 위험이 된다 |

공통으로 한 줄 알린다: **비밀번호가 없으면 주소를 아는 사람은 다 본다.** 그리고 **남에게 무엇을 깔라고 요구하지 않는다.**
